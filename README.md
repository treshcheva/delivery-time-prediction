# Delivery Time Prediction

ML-проект: прогнозирование времени доставки заказа по параметрам заказа, склада, трафика и погоды.

## Содержание

- `delivery_time_prediction.ipynb` — анализ данных, подбор и сравнение моделей, итоговая оценка на тестовой части размеченного набора.
- `data/train.csv` — положите сюда размеченный датасет с колонкой `delivery_time_days`.
- `requirements.txt` — зависимости проекта.

Данные не включены в репозиторий. Для воспроизведения результата нужен только `train.csv`.

## Запуск

1. Установите зависимости: `pip install -r requirements.txt`.
2. Поместите `train.csv` в `data/`.
3. Запустите `delivery_time_prediction.ipynb` сверху вниз.

## Методология и результат

Из 4 000 размеченных строк фиксированным разбиением выделяются 3 200 строк в обучающую выборку и 800 строк в тестовую выборку. Идентификатор `id` исключён из признаков. На обучающей выборке выполняется 5-fold подбор гиперпараметров; кандидаты сравниваются по MAE. IQR-фильтрация встроена в estimator, поэтому границы вычисляются только на обучающей части каждого CV-fold. Тестовая выборка не используется для EDA, подбора и выбора эксперимента.

На текущем запуске по CV MAE выбран `IQR-filtered tree` (CV MAE: **1.9407 дня**). Дополнительный признак «расстояние / вес» не улучшил CV MAE (**1.9446 дня**). На тестовой выборке MAE медианного baseline, настроенного обычного дерева и выбранной модели составил **4.4613**, **2.1035** и **1.6354 дня** соответственно. Для выбранной модели RMSE — **4.4193 дня**, R² — **0.5000**. Модель выбирается по CV до просмотра тестовых метрик; тестовые значения приведены для финального отчёта, а не для выбора победителя. Они не являются гарантией качества на будущих данных.

После финальной оценки модель остаётся обученной только на обучающей выборке: это позволяет сохранить независимую оценку на тестовой выборке. Если модель понадобится применять на новых данных, её можно отдельно переобучить на всех размеченных строках, понимая, что для такой версии уже не будет независимой оценки на этом наборе.
